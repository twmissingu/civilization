# 文明6 开源复现 · 产品需求文档（PRD）

> 版本：v0.1（Phase 1 MVP）　日期：2026-07-12　状态：已对齐，待开发
> 技术栈：Web（TypeScript + PixiJS + React + Vite）　美术：手绘插画风（AI 生图）
> 定位：分阶段交付，Phase 1 = 可玩 MVP，北极星 = 文明6 基础版全机制

---

## 问题陈述（Problem Statement）

4X 回合策略游戏爱好者想要一款**免费、开源、浏览器即开即玩**的文明6 风格作品，但现状没有满足需求的选项：

- 文明6 本体是付费商业游戏，且为桌面客户端，无法浏览器即开即玩，也无法自由修改扩展。
- 现有开源文明克隆都基于更早的文明版本——FreeCiv/FreeCiv-web 对标文明2，Unciv 对标文明4——**都没有复现文明6 的两个签名机制**：「区域拆城 + 相邻加成」与「市政树 + 政策卡政体」。玩家想要的是文明6 那套"城市在格子上铺开、文化进度与科技并行、政体可切换卡槽"的玩法，而不是老版本的堆叠城市。
- 现有克隆的美术要么是像素/简笔，要么依赖原版资源，缺乏一套统一、精美、原创的手绘插画美术。

换言之：**没有一个免费、开源、浏览器可玩、且真正复现文明6 签名机制的 4X 策略游戏。**


## 解决方案（Solution）

用**纯 Web 开源技术栈**（TypeScript + PixiJS 渲染 + React HUD + Vite 构建）从零构建一款浏览器即开即玩的回合制 4X 策略游戏，**分阶段复现文明6 的核心循环与签名机制**：

- **Phase 1（本 PRD 范围）= 可玩 MVP**：3 个可玩文明、精简科技树（~35 节点）、精简市政树+政体政策、六边形地图（~60×36）、建造者充能制、区域+相邻加成、基础战斗、2 个 AI 对手、3 种胜利（科技/统治/分数）、存档读档。目标是**一条完整的"探索-扩张-开发-消灭"闭环能玩通**。
- **北极星 = 文明6 基础版全机制**：在 MVP 架构上持续叠加城邦、大人物、宗教、贸易、间谍、完整 70+ 科技/市政、8+ 文明、全部 5 种胜利，最终对齐基础版。
- **美术全部由 `/jiuqing-image-generate` 生成**，统一手绘插画风（羊皮纸+金边 UI、油画领袖肖像、手绘地形贴图），保证原创、精美、风格一致。
- **架构上把"确定性游戏规则层"与"渲染/输入层"彻底分离**：规则层是纯 TypeScript 模块、可被 Vitest 自动化测试、不依赖浏览器/画面；这也正是未来加联机（确定性同步）的基础。MVP 仅单机+AI，联机只留接口不做。

从玩家视角：打开浏览器就能开始一局文明，建城、铺区域、攀科技、走市政、打仗、冲胜利，体验文明6 那套"拆城+文化并行"的核心爽感，且完全免费、可改、可扩展。


## 用户故事（User Stories）

### 地图与开局
1. 作为玩家，我想在进入游戏后由系统随机生成一张六边形地图（含地形、地貌、资源、沿海/内陆），以便每局都有不同体验。
2. 作为玩家，我想在开局看到一张带战争迷雾的世界地图，只有我单位周围可见、已探索区域保留地形记忆，以便有探索的驱动力。
3. 作为玩家，我想选择 3 个文明之一、选择领袖，并选定地图尺寸/难度，以便定制本局体验。
4. 作为玩家，我想开局拥有一名开拓者和一名战士（标准文明式开局），以便立刻能建城与自卫。
5. 作为玩家，我想用鼠标/键盘平移、缩放镜头，以便纵览全局或聚焦局部。

### 城市与扩张
6. 作为玩家，我想让开拓者走到合适格子建城，城市即刻占据周边一格并随文化扩张领土，以便确立立足点。
7. 作为玩家，我想在城市界面看到人口、住房、宜居度、各格产出、已建/在建建筑与区域，以便规划发展。
8. 作为玩家，我想用金币购买地块、用文化自动扩张新地块，以便控制城市版图。
9. 作为玩家，我想分配市民到不同地块工作（或由系统自动分配），以便优化食物/产能/金币等产出。
10. 作为玩家，我想在城市周边格子放置**区域**（如学院、商业中心、圣地、工业区、军营、港口、剧院），并看到**相邻加成**实时计算与提示，以便体验文明6 的"拆城"签名机制。
11. 作为玩家，我想建造奇观（如大金字塔、紫禁城），奇观占用专属格子并给予全局加成，以便有长期目标感。
12. 作为玩家，我想在城市生产队列里排队单位/建筑/区域/奇观，并可调整顺序，以便批量规划。

### 建造者与地块改良
13. 作为玩家，我想用建造者（充能制，默认 3 充能）改良地块（建农场、矿山、种植园、牧场、伐木场、渔船等），每次消耗 1 充能，以便体验文明6 的建造者签名机制。
14. 作为玩家，我想看到改良后的地块产出提升、且部分改良受科技解锁（如化肥提升农场、 apprenticeship 提升矿山），以便科技与产出挂钩。
15. 作为玩家，想修路（由贸易路线自动铺设，或工人后期修筑）以提升单位移动，以便部队调度更快。（MVP: 道路推迟，贸易路线归 Phase 2）

### 科技树
16. 作为玩家，我想在科技树界面看到一条按时代排列的节点网络（精简版约 35 节点），已研究/可研究/锁定状态清晰，以便规划科技路线。
17. 作为玩家，我想每回合积累科技值推进当前研究，满足**尤里卡**条件时获得 +40% 加速，以便有目标性触发加速。
18. 作为玩家，我想研究某科技后解锁对应单位/建筑/区域/奇观/改良，以便科技带来实质变化。
19. 作为玩家，想看到当前研究进度条与剩余回合数估算，以便掌握节奏。

### 市政树与政体政策（签名机制）
20. 作为玩家，我想在市政树界面看到与科技树并行的文化进度网络，满足**灵感**条件时获得加速，以便文化与科技双线推进。
21. 作为玩家，我想在解锁市政后获得新的**政策卡**（军事/经济/万能），以便组合自己的政策。
22. 作为玩家，我想切换**政体**（酋邦→寡头→独裁→古典共和→君主→神权→商业共和→民主…），不同政体给不同数量/类型的政策槽与加成，以便策略性选择治理方式。
23. 作为玩家，想在不消耗回合的情况下随时换卡（或受政体约束），以便灵活应对局势。
24. 作为玩家，想看到政体与政策卡带来的加成在产出/战斗/外交上的实际数值体现，以便决策有据。

### 单位与移动
25. 作为玩家，我想选中单位后看到可移动范围高亮（受地形移动力消耗、控制区 ZOC、河流/海洋限制），以便规划行军。
26. 作为玩家，想用 A* 寻路让单位自动走到目标格（绕开不可通行/敌区），以便减少操作负担。
27. 作为玩家，想让单位每回合按移动力行动、移动力用尽则灰显，以便理解回合制节奏。
28. 作为玩家，想让军事单位晋升（战斗经验升级、选晋升树节点）、维护费每回合扣金币，以便养成老兵。
29. 作为玩家，想让多个单位堆叠有限（文明6 规则：军事+平民/支援各一，同类型不可堆叠），以便遵守规则。
30. 作为玩家，想让建造者/开拓者等平民单位受军事单位护卫，被敌方军事单位接触时可被俘获/消灭，以便有风险感。

### 战斗
31. 作为玩家，想发起近战/远程攻击并看到战斗力对比与预期伤害，以便评估是否开战。
32. 作为玩家，想战斗结果按文明6 公式结算（基础力+修正：地形、夹击、支援、晋升、政策、血量衰减），并看到双方掉血与可能死亡，以便战斗可预测。
33. 作为玩家，想攻城时受城墙与城市防御力影响、需攻城单位（攻城塔/攻城武器）才能高效破墙，以便攻城有策略。
34. 作为玩家，想占领敌方城市（血量打空后进占），占领原始首都计入统治胜利，以便有征服目标。
35. 作为玩家，想看到控制区（ZOC）限制敌方单位贴身穿插，以便利用阵型。

### AI 对手
36. 作为玩家，想要 2 个 AI 文明同样建城、攀科技、建军、扩张、宣战/求和，以便有对抗感。
37. 作为玩家，想 AI 的行为有基本合理性（优先抢奇观、遇弱则攻、遇强则守/求和），而不是纯随机，以便有挑战。（注：城邦相关 AI 行为随城邦系统一并延后至 Phase 2。）
38. 作为玩家，想选择 AI 难度（3 档：简单/标准/困难），难度影响 AI 起始加成与决策质量，以便调节挑战度。
39. 作为玩家，想 AI 每回合决策在可接受时间内完成（小地图 60×36、3 文明、2 AI 下单回合 < 3 秒；后期满载 2 AI×15 城×40 单位须附基准），以便不卡节奏。

### 胜利与终局
40. 作为玩家，想冲**科技胜利**：完成航天三段任务（发射卫星→登月→火星殖民），以便有和平攀科技的目标。
41. 作为玩家，想冲**统治胜利**：占领全部其他文明的原始首都，以便有征服目标。
42. 作为玩家，想冲**分数胜利**：到设定回合上限时按综合分数（城市/人口/科技/奇观/领土等）判定，以便有兜底终局。
43. 作为玩家，想任一胜利触发时看到结算画面（排名、耗时、关键统计），以便有收尾成就感。
44. 作为玩家，想中途随时看到本文明在各项胜利进度上的排名与差距，以便调整策略。

### 界面与体验
45. 作为玩家，想有顶部资源条（科技/文化/金币/信仰/宜居度/战略资源/铁/煤等）实时显示，以便一眼掌握国力。
46. 作为玩家，想有科技/市政/生产/外交等一键打开的面板，以便快速操作。
47. 作为玩家，想单位/城市/地块 hover 有 tooltip 说明产出与规则，以便降低学习门槛。
48. 作为玩家，想回合结束有"等待操作"提示（还有单位可动/城市闲置时确认再结束），以免误操作。
49. 作为玩家，想随时保存/读取存档（本地 IndexedDB + 导出 JSON 文件），以便跨会话续玩。
50. 作为玩家，想支持中文界面为主、保留文明经典英文术语（如 Science/Culture/Eureka），以便亲切又专业。
51. 作为玩家，想画面是统一手绘插画风、UI 带羊皮纸+金边质感、领袖肖像是油画风，以便获得精美沉浸感。
52. 作为玩家，想镜头聚焦事件（如奇观建成有建造成就图与动画、战斗有粒子特效），以便有仪式感。

### 边界与异常
53. 作为玩家，想当地图无可达路径时单位给出提示而非卡死，以便不困惑。
54. 作为玩家，想当城市被围困/忠诚度相关机制（MVP 简化为宜居度过低触发叛乱概率）时给出警告，以便应对。
55. 作为玩家，想存档损坏时有错误提示而非崩溃，以便容忍异常。
56. 作为玩家，想在窄屏（平板）下界面自适应可用，以便非桌面也能玩（MVP 保证桌面优先，平板尽量不崩）。


## 实现决策（Implementation Decisions）

### 技术栈与运行时
- **语言**：TypeScript（严格模式），贯穿逻辑层与渲染层。
- **构建/开发**：Vite，秒级 HMR 热重载，便于 agent 迭代与浏览器即时预览。
- **渲染层**：PixiJS（WebGL 批渲染六边形瓦片、单位精灵、粒子、迷雾），负责游戏世界画面。
- **UI/HUD 层**：React + Zustand（轻量状态管理），负责科技树/市政树/城市屏/资源条/外交等界面；Framer Motion 做过渡动画。
- **状态桥（多通道，单向数据流）**：逻辑层对外暴露四类通道——
  - (a) **快照**：不可变（结构化共享/Immer），渲染层经 selector 分片订阅 + shallow equal 跳过未变更切片，禁止整快照订阅；
  - (b) **命令 API**：写入，走两阶段校验（见确定性约束）；
  - (c) **查询 API**：纯函数，输入快照+参数返回结果不变更状态（用于预览相邻加成、可达范围、不可达原因）；
  - (d) **事件**：命令执行副产品 `{ type, turn, payload }`，驱动动画/音效/日志，不进 GameState、不参与序列化，丢失只影响表现不影响正确性。
- **三类状态分离**：(a) 游戏状态（逻辑层快照，确定性，可序列化）；(b) UI 交互状态（Zustand，非确定性，不存档：选中/hover/面板/镜头）；(c) 渲染瞬时状态（Pixi 内部：动画进度/粒子/插值）。三者不交叉写入。
- **发射频率合约**：玩家回合每次命令一个新快照；AI 回合变更批处理（≤100ms 窗口合并）；renderer 固定 60fps，每帧至多消费一个合并后快照。
- **迷雾可见性**在逻辑层计算，快照每格带 `visibility`（unexplored/explored/visible），渲染层只按状态出遮罩。
- **存档**：游戏状态序列化为 JSON，存 IndexedDB 并支持导出/导入文件。
- **测试**：Vitest（逻辑层单测/场景测）；渲染层不写单测，仅冒烟。

### 架构分层（核心决策）
- **逻辑层（headless、确定性、纯 TS）**：游戏状态机 + 规则引擎。包含六边形数学、寻路、战斗结算、科技/市政推进、城市增长与产出、区域相邻加成、建造者充能、AI 决策、胜利判定、存档序列化。**不 import 任何浏览器/DOM/Pixi/React**，可在 Node 下直接跑测。
- **渲染层**：PixiJS 场景图（瓦片层/单位层/特效层/迷雾层）+ React HUD，只读逻辑快照、只发命令。
- **AI 子层**：基于效用函数（utility AI）的决策器，MVP 不上复杂规划；输入游戏快照、输出命令序列。确定性（固定 seed 可复现）。
- 该分层同时满足：自动化测试、未来联机（确定性同步只需广播命令/种子）、未来换皮（渲染可替换）。

### 确定性约束（逻辑层硬性规则，产品级不变量）
- 逻辑层禁止调用 `Math.random()`、`Date.now()`、`performance.now()` 及任何非确定性 API；由 lint 规则 + 依赖审查强制。
- 所有随机性经单一 `Rng` 接口注入，由游戏 seed 初始化；子系统经 `rng.fork(name)` 派生子流，互不干扰。`Rng` 内部状态可序列化。
- 命令为 plain object（可 `JSON.stringify`），执行为纯函数 `(state, command) => { state, events }`，禁止副作用/IO/非确定性 API；随机性只能经 state 内 `Rng` 取得。
- 命令两阶段校验：`validate`（结构）→ `canExecute`（语境，暴露给 UI 做按钮可用性）→ `execute`；非法命令不改状态、不消耗 RNG。
- 存档格式 `{ version, createdAt, state, rngState }`；`version` 为整数 schema 版本号，配套链式迁移 `migrate(from, data)`；加载校验失败返回明确错误码（对应用户故事 55）。
- `GameState` 可序列化字段禁用 `Map`/`Set`/`BigInt`，改用 plain object 或有序数组；自定义类型实现 `toJSON`/`fromJSON`。
- 回合结算与命令解析按固定序：玩家按 ID 升序、城市/单位按 ID 升序；一回合多命令入队按固定序解析。
- 可累计数值（科技/文化/产能/金币/信仰）内部以整数存储（×100），百分比加成转整数乘除后取整，禁浮点累计与浮点 `===`。
- 逻辑层零浏览器依赖：只产出/消费序列化数据，不负责 IndexedDB/文件 IO（由浏览器层处理）。

### 六边形与地图
- **坐标系**：轴向坐标（axial, q/r），便于邻接/距离/寻路计算；与偏移坐标互转用于存档可读性。
- **朝向**：pointy-top（尖顶六边形）。轴向->像素：`x = size * (sqrt(3)*q + sqrt(3)/2*r)`，`y = size * (3/2*r)`（size=半径，tile 贴图 256×256，详见 `docs/art-spec.md`）。
- **地图尺寸**：MVP 小地图 60×36（≈2160 格），有界矩形（非环面），边界 q ∈ [0,59]、r ∈ [0,35]，边缘外视为不可通行。
- **地图生成**：基于噪声（Simplex）生成海拔+湿度->地形+地貌+资源分布；噪声参数与分桶阈值详见 `docs/mapgen.md`。
- **寻路**：A*，代价=地形移动力消耗，处理 ZOC、河流过河惩罚、不可通行（山脉/海洋对陆地单位）。
- **迷雾可见性**：逻辑层计算，单位视野 = 其 `vision` 半径内六边形集合（MVP 不考虑地形遮挡）；快照每格带 `visibility`（unexplored/explored/visible）。M1 空场景默认全 visible 便于调试。

### 玩法系统（MVP 范围）
- **城市**：开拓者建城、文化扩张（按文化值累积逐格扩张）、金币买地、人口增长（食物溢出）、住房/宜居度（宜居度过低触发叛乱概率，MVP 简化）。
- **区域与相邻加成（签名）**：MVP 至少实现学院、商业中心、圣地、工业区、军营、剧院、港口（若临海）共 7 种区域（机场归 Phase 2），相邻加成按文明6 规则（如学院邻山脉/地热+科技，商业中心邻河流/港口+金币），UI 实时显示加成预估。
- **科技树**：精简 ~35 节点，跨时代（远古->古典->中世纪->文艺复兴->工业->现代->原子能->信息），含尤里卡。
- **市政树+政体政策（签名）**：精简市政树，政体含酋邦/寡头/独裁/古典共和/君主/神权/商业共和/民主，政策卡分军事/经济/万能槽（外交卡枚举预留 Phase 2）。
- **建造者充能（签名）**：默认 3 充能，每次改良消耗 1，可通过政策/奇观/金字塔增加。
- **单位**：建造者、开拓者、战士、弓手、投石、骑兵系、攻城系、海军（近战/远程）；晋升树精简。
- **战斗**：文明6 战斗力公式（基础力 + 地形/夹击/支援/晋升/政策/血量修正），近战/远程/攻城，城墙与城市防御，ZOC。
- **胜利**：科技（航天三段）、统治（占全部原始首都）、分数（回合上限综合分）。

### 文明（MVP 3 个）
- 每个文明含：文明能力 + 领袖能力 + 1 特色单位 + 1 特色建筑/区域/基础设施。
- 选型倾向经典且机制差异化（如一个偏科技/一个偏军事/一个偏文化），具体 3 个待开发启动时定稿（建议参考：罗马式军事扩张、中国式科技/人口、希腊式文化/政体）。

### 美术与资产生成
- 全部美术由 `/jiuqing-image-generate` 生成，统一手绘插画风；建立**资产清单 + 风格 prompt 模板**保证一致性。
- 资产类别：地形贴图（各类地形×地貌组合）、资源图标、单位精灵、建筑/区域/奇观插画、领袖肖像、文明徽记、UI 装饰元素（面板/按钮/边框/图标）、科技/市政节点插画、胜利结算图。
- 资产经 Pixi spritesheet 打包；UI 装饰元素供 React 使用。
- 配色与笔触在 prompt 模板中固定（暖色羊皮纸底、金边、油画肖像、手绘地形），避免风格漂移。

### 美术-数据接口（assetId 桥接）
- 逻辑层（headless）不 import 任何美术资产，玩法数据结构只携带稳定 `assetId` 字符串（`ResourceDef.iconAssetId`、`UnitDef.spriteAssetId`、`DistrictDef.mapIllustrationId`、`WonderDef.achievementImageId`、`LeaderDef.portraitAssetId`、`TechNode.illustrationId` 等）。
- 渲染层维护 `AssetManifest`（`assetId -> Pixi Texture / React 资源路径`）映射表，按 assetId 查找。
- 命名前缀：`terrain_`/`feature_`/`res_`/`unit_`/`district_`/`building_`/`wonder_`/`portrait_`/`tech_`/`civic_`/`gov_`/`policy_`/`ui_`；后缀 `_map`/`_icon`/`_achievement`/`_idle`/`_move`/`_attack`。详见 `docs/art-spec.md`。

## 测试决策（Testing Decisions）

> 本项目为全新空仓库，无现有代码/同类测试可参照，测试决策基于本 PRD 定义的目标架构提出。

### 测试接缝（Seam）
- **主接缝：确定性游戏逻辑层（headless pure TS）**。所有玩法规则测试都从这个最高公共入口切入，不依赖 Pixi/React/浏览器，可在 Node + Vitest 下直接跑。这是覆盖最多代码路径、最高杠杆的接缝。
- 渲染层（PixiJS/React）不写单元测试，仅做冒烟（能挂载、能读快照渲染不报错），因为业务逻辑已下沉到逻辑层、渲染层应尽量薄。

### 什么是好测试
- **只测外部行为，不测实现细节**：测"给定游戏状态 + 命令 -> 产生的新状态/事件"，不测内部私有函数与数据结构。
- **确定性、可复现**：所有涉及随机的测试用固定 seed，保证失败可重放。
- **场景化优先**：用剧本式测试覆盖完整流程（如"建城->改良->研究->造兵->攻击->占领"一条龙），优于零散单测。

### 将测试的模块（对应主接缝）
- 六边形数学：坐标转换、邻接、距离、范围。
- 寻路（A*）：地形代价、ZOC、河流、不可通行、绕行正确性。
- 战斗结算：近战/远程/攻城、城墙、夹击/支援/晋升/政策修正、血量与死亡、占领首都判定。
- 科技/市政推进：科技值/文化值累积、尤里卡/灵感触发、解锁联动、政体与政策卡切换合法性。
- 城市与产出：扩张、买地、市民分配、产出计算、区域相邻加成（签名机制重点测）。
- 建造者充能制：充能消耗/补充、改良解锁与产出联动。
- AI 决策：固定 seed 下决策可复现；剧本测（如"AI 在弱邻旁会宣战"）。
- 胜利判定：科技三段、统治占首都、分数计算与终局触发。
- 存档序列化：状态 -> JSON -> 还原状态，等价性 round-trip 测试。

### 参照与质量门
- 参照开源项目架构思路：Unciv（逻辑/UI 严格分离、可测的游戏引擎）、FreeCiv（规则引擎与前端解耦），作为逻辑层可测性的设计参照（不抄代码，借鉴分层）。
- 质量门（详见 `docs/testing/`）：逻辑层关键路径清单（CP-01…）每条存在对应通过的场景测试；覆盖率阈值（Vitest + @vitest/coverage-v8，仅逻辑层）写入 `vitest.config.ts` 并在 CI 门禁；新增玩法须附带至少一个场景测试（CI 校验 `src/rules/**` 改动须有对应 `tests/scenarios/**`）。

## 范围之外（Out of Scope）

**本 PRD（Phase 1 MVP）明确不做：**
- **联机/多人**：MVP 仅单机+AI；架构预留确定性同步接口但不实现网络层。
- **DLC 系统**：宗教、间谍、大人物、城邦、贸易路线、总督、时代/黄金黑暗时代、忠诚度完整系统、紧急状况、天气/自然灾害、气候变化、电力系统、未来时代、世界大会、外交胜利、地形工程（铁路/隧道/运河）、摇滚乐队--全部留待后续阶段。
- **完整科技/市政树**：MVP 用精简版（~35 节点），非基础版完整 70+ 节点。
- **8+ 文明**：MVP 只做 3 个文明。
- **全部 5 种胜利**：MVP 只做科技/统治/分数 3 种（文化、宗教胜利后续）。
- **本地化**：MVP 仅中文为主，不做多语言切换。
- **移动端原生打包**：MVP 保证桌面浏览器优先、平板尽量不崩，不做 iOS/Android 原生包。
- **在线排行榜/账号系统**：不做。
- **Modding/编辑器**：不做（后续阶段考虑）。
- **音频/配音**：MVP 不含，后续可加背景音乐与音效。
- **教程战役**：MVP 不做战役剧本，仅自由对战。

**北极星（后续阶段，非本 PRD 范围）**：在 MVP 架构上叠加，最终对齐文明6 基础版全机制；再视情况考虑 Rise & Fall / Gathering Storm DLC 系统。

## 范围裁决（MVP 边界澄清）

经评审收敛，以下 MVP 范围内悬空/矛盾项裁决如下：

- **圣地与信仰值**：MVP 保留圣地（产信仰值），信仰值**计入分数胜利、不做主动消费**；宗教系统（万神殿/传教/宗教胜利）显式排除，留待 Phase 2。理由：避免死资源、避免与文化产出重叠、保留圣地相邻加成签名、Phase 2 可复用。
- **外交边界**：MVP 外交 = **仅 peace/war 双状态机**（declare_war / sue_peace 为唯一转换），无同盟/交易/世界大会/外交胜利。AI 宣战效用驱动于军力比/地理/战略，不依赖外交政策卡。**政体表 MVP 只含军事/经济/万能槽（不设外交槽）；`PolicyCardType` 枚举保留 `diplomatic` 为 Phase 2 预留，MVP 不发放外交卡。**
- **US37"会争夺城邦"**：已删除该条款（城邦系统排除，留待 Phase 2）。
- **政体全集**：MVP 做 8 种（酋邦/寡头/独裁/古典共和/君主/神权/商业共和/民主），无"+可选后期"。
- **区域全集**：MVP 做 7 种（学院/商业中心/圣地/工业区/军营/剧院/港口），**机场归 Phase 2**。
- **显式排除清单（cut list）**：见"范围之外"节；任何超出上限（科技≤35 节点/文明=3/胜利=3/区域≤7/政体≤8/奇观≤5）需范围变更请求。

## 其他说明（Further Notes）

### 分阶段路线图
- **Phase 1（本 PRD）**：可玩 MVP，3 文明 + 精简树 + 签名机制 + 3 胜利 + AI + 存档。
- **Phase 2**：补齐区域/奇观全集、完整政体、城邦、大人物、贸易路线、宗教、文化胜利。
- **Phase 3**：完整 70+ 科技/市政、8+ 文明、全部 5 胜利、多 AI 难度梯度、平衡调优。
- **Phase 4（北极星达成后）**：评估是否引入 DLC 系统（时代/总督/灾害/电力/外交胜利等）。
- **Phase 5**：联机（基于已预留的确定性同步层）、Modding、移动端打包、音频。

### 技术选型备注
- 调研对比了 Godot 4 / Bevy(Rust) / Phaser / PixiJS：选 Web(TS+PixiJS+React) 的核心理由是 agent 协作开发迭代最快（TS 是 LLM 最熟语言、Vite HMR 秒级、文件驱动）、浏览器零安装分发、回合制 4X 不需引擎级实时性能、与 /jiuqing-image-generate 资产接入最顺。Godot 为备选（若后期需要原生引擎工具链可评估迁移，但 MVP 不采用）。

### 开源与许可
- 项目拟采用 MIT 许可证，全部代码与生成资产开源。美术资产为 AI 生成原创，不依赖文明6 原版资源，避免版权问题；文明/领袖选型用"参考式"机制差异化，不照搬商标化内容。

### 参考项目
- Unciv（Kotlin，文明4 风格）：借鉴其逻辑/UI 严格分离与可测引擎架构。
- FreeCiv / freeciv-web：借鉴其规则引擎解耦与六边形地图实现思路。
- hexx（Rust crate）/ 社区六边形算法资料：轴向坐标与网格算法参考。

### 风险与缓解
- **美术一致性风险**：AI 生图易风格漂移 -> 用固定 prompt 模板 + 资产清单 + 人工筛选，建立风格基准图。
- **平衡调优成本**：4X 平衡难 -> MVP 先求"能玩通且无明显破绽"，平衡留 Phase 3 专项。
- **范围蔓延风险**：签名机制与核心闭环优先，DLC 内容严格挡在 Phase 1 之外。
- **agent 生成代码质量**：逻辑层 headless + 高覆盖自动化测试兜底，渲染层薄、易替换。
